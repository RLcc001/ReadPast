# 让 R1 先亮出误弃答代价，再谈贡献

在流式视频、多模态 VQA 和文本 RAG 三个领域里，R1 用的判据有一整个 PMI 家族的近亲，包括 CAD、PMI_DC、M3ID、音视频的 RED 和 ClashEval 的概率校正。这个判据就是被选选项 o* 在"有画面±时间线"和"只读题目"两路下、在非弃答选项上重归一化后的对数概率差。但本轮调研**没有找到任何工作直接拿这个差的符号，在带弃答选项的选择题上免训练地触发弃答**。这是 R1 可以主张的空白，代价是没有现成的阈值和评测先例可借。

文献对这类判据的失败方式记录得很一致：固定强度的有/无证据对比，尤其是只看比值的纯 PMI，会系统性地误伤"先验已经能答对、证据只是冗余"的样本。CAD 在无冲突的 NQ-Synth 上从 88.2 跌到 64.0；PVI、Sufficient Context 和 BICR 都明确指出，"证据没提供额外支持"不等于"答错"。R1 在记忆题上 16–20% 的误弃答就是这个问题。

评估上也有结构性漏洞。OVO 的 HLD 只包含应弃答的样本，而 R1 只会把答案往弃答方向改，这正是 Mirage 警告的"单向修改制造虚假增益"。成熟做法都会把弃答选项也加到可答题上，并单独报告过度拒答。流式社区已经把 HLD 单列，OVO 自己的纯文本 GPT-4-turbo 在 HLD 上更是拿到 70.05，高于所有视频模型。

据此有三条建议：
- **论文主张**：ReadPast 的记忆主张只建立在不含 HLD 的数字上，R1 降为在主表单独占一行、正文给出双侧代价的答案端插件。
- **设计**：把硬符号检验改成带置信门控、用可答题的无标签分布定阈值的版本。
- **评估**：补齐"永远弃答 / 只靠弃答 prompt / 等弃答率随机弃答 / 等弃答率低置信弃答"四条对照。

最便宜、也最能定方向的一步，是在可答题上注入弃答选项，算出 R1 在答错题和答对题上的**翻转率之比**。这个比值直接决定 R1 进正文当组件，还是放进附录当一段分析。

> 阅读约定：带链接的陈述是文献证据。标【推断】的内容是基于文献的推理，没有论文直接验证过。R1 自身的数字来自项目内部实验，包括 HLD +13～15、总分 +2.2～2.6、记忆题误弃答 16–20%、实时题误弃答 3.5–6%、HLD 幻觉召回 26–35%。部分引文经网页抓取工具摘要转述，写进论文前需回原文逐字核对。

## R1 的判据有一整个 PMI 家族，但没人拿它的符号直接弃答

R1 计算的量是 log p'_E(o*) − log p'_Q(o*)。形式上它就是限制在选项集上的条件点互信息，也可以改写成证据对 o* 的对数 Bayes 因子 log p(E|o*,Q) − log p(E|Q)。R1 的判决等价于"Bayes 因子 ≤ 1 就弃答"。这个量在三个领域都很常见，但没有一处拿它来弃答。

- **文本侧**：
  - CAD 用 softmax[(1+α)·logit(y|c,x) − α·logit(y|x)] 做 token 级重加权，α 按任务手设为 0.5 或 1（[CAD](https://ar5iv.labs.arxiv.org/html/2305.14739)）。
  - PMI_DC 用 P(y|x,domain)/P(y|domain) 给选项打分，同样不设阈值（[PMI_DC](https://arxiv.org/abs/2104.08315)）。
  - FilCo 把比值阈值 1.0（即对数域的 0）当作区分"上下文增加还是减少输出概率"的分界，这是"零阈值"最直接的先例。但它依赖金标答案，只用于过滤训练数据（[FilCo](https://arxiv.org/html/2311.08377)）。
- **多模态侧**：M3ID 对比有图与无图的对数概率，并且**只在有图模型的 top 概率低于阈值时才施加修正**（[M3ID](https://arxiv.org/html/2403.14003)）。
- **与 R1 最像的是音视频的 RED**：它计算 Δ = log p^S(w) − log p^Q(w)，question-only 分支由同一个冻结模型给出，还用 100 道**无标签**题估计中心化偏移 η。但 RED 用这个量做解码，不处理弃答（[RED](https://arxiv.org/html/2610.02976v1)）。
- **流式场景**：StreamOPD 的 ST-CueGate 算的是同一种有/无线索似然比，但只拿来当蒸馏的训练权重（[StreamOPD](https://arxiv.org/html/2608.16320)）。

把"有证据 vs 无证据"做成离散决策的工作很少，而且都带额外结构。ClashEval 的 token 概率校正在先验答案概率更高时改用无上下文答案，不设阈值。但作者发现，有上下文时的概率"极度右偏"，先验则"近乎均匀"，直接比较原始概率有偏，于是改为比较百分位。改动后 GPT-4o 的准确率从 0.615 升到 0.754，代价是 Prior Bias 从 0.021 升到 0.085（[ClashEval](https://arxiv.org/html/2404.10198)）。CDA 把显式弃答 prompt 下的分布作为第三路混入，只在参数与上下文两路都不确定时才加大弃答权重（[CDA](https://arxiv.org/html/2412.12527)）。SABER 用两个轻量预测器做四格决策：信参数、信上下文、两者都信、弃答（[SABER](https://arxiv.org/abs/2605.18792)）。【推断】这两种方法都单独设了"参数知识已够用，就不弃答"这一格，R1 没有。这是 R1 误弃答的结构性来源。

流式视频文献里，HLD 的大幅提升来自另外四条路线，没有一条是推理期的有/无证据对比：

1. **prompt 硬规则**：FOLIO 把 Qwen3-VL-8B 的 HLD 从 43.6 拉到 84.6。正文只用一句"conservative answer calibration"带过，真正的机制写在附录 K.3 的答案 prompt 里，原文是 "prefer 'Unable to answer' (when available) over guessing"（[FOLIO](https://arxiv.org/html/2607.13298)）。
2. **监督训练弃答**：SPARE 只用 173 条样本做 LoRA，HLD 从 42.47 升到 90.32（[SPARE](https://arxiv.org/html/2610.14671)）。OneStreamer 的训练数据里有"Answerability judgment"一类，HLD 从 41.9 升到 99.5，正文没有解释（[OneStreamer](https://arxiv.org/html/2610.01762)）。
3. **RL 惩罚错误作答**：StreamScout-R 通过奖励设计让"猜"的期望收益为负，Qwen3-VL-8B 的 HLD 达到 98.39（[StreamScout](https://arxiv.org/html/2609.00291)）。
4. **减少视觉上下文**：SimpleStream 里 Qwen3-VL-8B 在 2/4/8 帧下 HLD 依次为 54.8/52.1/50.5，加视觉 RAG 后 HLD 下降 12.4 点（[SimpleStream](https://arxiv.org/html/2604.02317)）。D-HSM 只用文本记忆时 HLD 为 91.40，只用最近 4 帧时为 51.61（[D-HSM](https://arxiv.org/html/2608.30294)）。

视频领域免训练的幻觉缓解方法，如 TCD 和 SEASON，做法都是**扰动**视频而不是移除视频，再做 logit 对比，从不输出弃答（[EventHallusion](https://arxiv.org/html/2409.16597)、[SEASON](https://arxiv.org/html/2512.04643v1)）。所以 R1 可以主张自己是第五条路线：推理期、免训练、用有/无证据对比做离散的弃答决策。但"没找到"不等于"不存在"。同期 ICLR 2027 投稿 ADP 声称做到免训练、免生成的可答性估计，本轮只读到它的摘要，投稿前必须核对（[ADP](https://openreview.net/forum?id=9qhFrlcwIi)）。

| 工作 | 比较的两路 | 用途 | 强度 / 阈值 | 是否弃答 |
|---|---|---|---|---|
| RED | 音视频证据 vs 只读题目（同一冻结模型） | token 级解码 | 无强度系数；η 由 100 道无标签题中心化 | 否 |
| ST-CueGate | 有/无线索 | 蒸馏训练权重 | α_g = 0.5，组内标准化 | 否 |
| CAD | 有/无上下文 | token 级解码 | α = 0.5 或 1，手设 | 否 |
| PMI_DC | 有题 vs 只有领域前提 | 选项打分 | 无 | 否 |
| M3ID | 有/无图 | token 级修正，仅在 top 概率低时启用 | 在带标注留出集上网格搜索 | 否 |
| ClashEval TPC | 有/无上下文的答案概率 | 二选一：改用先验答案 | 无；校准版比较百分位 | 否（改答） |
| CDA | 参数 / 上下文 / null / 弃答四路 | 软混合，含弃答分布 | 无硬阈值 | 是（软） |
| SABER | 参数答案 vs 上下文答案 | 四格决策 | 轻量预测器 | 是 |
| **R1** | 画面±时间线 vs 只读题目 | 对 o* 做符号检验 | 0，无标注 | 是（硬） |

## 纯 PMI 符号检验相当于 α→∞，误伤"先验已答对"的题是被反复记录的失败

CAD 这一脉的演化几乎就是 R1 问题的预演。

- **文本侧**：
  - 固定强度的对比在**无冲突**样本上掉点严重。Llama3-70B 在 NQ-Synth 上 greedy 得 88.20，CAD 只有 64.00；在 TriviaQA 上从 90.20 掉到 54.60。AdaCAD 把强度改成随两路分布的 JSD 自适应，NQ-Synth 回到 86.40（[AdaCAD](https://arxiv.org/html/2409.07394)）。
  - COIECD 同样记录到 CAD 在无冲突 NQ 上 EM 从 73.05 降到 67.50（[COIECD](https://arxiv.org/html/2402.11893)）。
  - CPMI 只在模型熵超过阈值时才启用 PMI，把 ROUGE-L 的代价从约 3.13% 压到约 0.977%（[CPMI](https://ar5iv.labs.arxiv.org/html/2210.13210)）。
- **多模态侧**：
  - PAI 加大先验减除强度 γ 后，MiniGPT-4 的 F1 从 70.3 降到 64.3（[PAI](https://arxiv.org/html/2407.21771)）。
  - M3ID 修正过强时覆盖率从 53.5 掉到 45.5，作者称之为过度补偿（[M3ID](https://arxiv.org/html/2403.14003)）。
- **惯例取值都很温和**：VCD 取 α=1（[VCD](https://ar5iv.labs.arxiv.org/html/2311.16922)），CMI-VLD 取 λ=0.5（[CMI-VLD](https://arxiv.org/html/2505.19678)），PAI 只减去 0.1 份先验。

【推断】product-of-experts 形式 p_E·(p_E/p_Q)^α 在 α 有限时保留了原分布，先验强、证据也强的答案不会被否决。R1 只看比值的符号，相当于 α→∞，把 p'_E(o*) 的绝对置信完全丢掉了。

样本层面的证据也一致指向"证据没提供额外支持 ≠ 答错"：
- PVI 原文写明负 PVI 的样本"仍可能被正确预测"，跨数据集的出错拐点在**约 0.5 bit，而不是 0**（[PVI](https://arxiv.org/abs/2110.08420)）。
- Sufficient Context 发现，上下文不充分时模型仍有 **35–62%** 能答对（[Sufficient Context](https://arxiv.org/html/2411.06037)）。
- BICR 发现对图像不敏感的样本大多是答对的，因此只对答对样本施加"有图置信高于黑图"的约束（[BICR](https://arxiv.org/html/2605.10893)）。
- PMI_DC 在 ARC-Easy 上输给原始语言模型打分，原因是正确答案恰好是"先验上就很可能"的常见答案（[PMI_DC](https://arxiv.org/abs/2104.08315)）。
- Reliable VQA 中只用问题特征的选择器，在 1% 风险下覆盖率仅 0.02%（[Reliable VQA](https://arxiv.org/abs/2204.13631)）。
- VSI 的作者建议把视觉不敏感信号当"条件集成组件"，而不是单独的判决器（[VSI](https://arxiv.org/abs/2609.00868)）。

【推断】R1 的内部数字和这个失败模式对得很整齐。记忆题被误弃答 16–20%，实时题只有 3.5–6%。记忆题的答案信息在过去，在 E 分支里要么只以压缩的文本时间线出现，要么根本不出现。所以即使 o* 是对的，证据对它的抬升也很小，R1 恰好惩罚了 ReadPast 的记忆想要服务的那类题。同时 R1 只抓到 26–35% 的 HLD 幻觉答案，作为检测器并不强。prompt 规则在 HLD 上远高于 R1（FOLIO 84.6），所以 R1 唯一可能的优势只剩"误弃答更少"，而这恰恰是目前还没量过的部分。

判决规则可以朝四个方向改。以下组合是【推断】，每条的文献先例已标注，每种改法都是拿 HLD 召回换误弃答，只能靠扫描、画 Pareto 曲线来挑工作点：
1. **加间隔**：要求 Δ ≤ −δ（δ>0）才弃答，对应 PVI 的 0.5 bit 拐点。
2. **加置信门**：只在 p'_E(o*) 低于 κ，或它与第二名差距很小时，才允许否决。对应 M3ID 的"top 概率低才修正"和 CPMI 的熵门控。
3. **从点比较升级为分布比较**：用 p'_E 与 p'_Q 的 JSD 或 KL，区分"证据没改变分布（冗余，应保留答案）"和"证据把概率质量从 o* 挪走（应怀疑）"。对应 AdaCAD 和 Du 等的 persuasion score（[Du et al.](https://arxiv.org/html/2404.04633)）。
4. **改用格子决策**：仿照 CDA 和 SABER，先验强且证据不反对时保留答案。

阈值"0"有天然的读法，即 Bayes 因子等于 1。但几乎所有"免训练"方法的超参，要么沿用惯例，要么在**带标注**集上调：
- M3ID 在 500 张 COCO 图上按 CHAIR 做网格搜索。
- CPMI 甚至在属于测试集的 500 条标注上调参。
- BERT 在 SQuAD 2.0 上的 no-answer 阈值，在 dev 集上按 F1 最大化选取（[BERT](https://ar5iv.labs.arxiv.org/html/1810.04805)）。
- Reliable VQA 的阈值在验证集上按 Φ_c 最大化选取。

无标签定尺度有三种先例：RED 用 100 道无标签题估计偏移；AdaCAD 把强度下限设为无冲突数据上 JSD 的最大值；ClashEval 改比百分位。StreamOPD 的组内标准化 (g−μ_G)/σ_G 也可以借来按题型标准化 Δ。如果允许少量标注，共形风险控制可以给出 E[R] ≤ α 的分布无关保证（[Conformal abstention](https://arxiv.org/html/2405.01563)）。

【推断】对 R1 最站得住的无标签方案是"翻转预算"。取实时、EPM、ASI 这些按构造必然可答的任务，注入弃答选项，不看金标，只看 Δ 的分布，把 δ 定在翻转率不超过 b% 的位置，例如 5%。这依赖"任务可答"这一弱监督，论文里要明说。如果继续把"无阈值"当卖点，就必须配上后面"评估"一节的伪基线。

## 先验分支不是中性参照：Zhao 式校准为何压垮弃答，还能怎么构造

Zhao 的 contextual calibration 用"N/A"、"[MASK]"和空串三种内容无关输入估计标签先验，再把它除掉。作者自己就发现，选哪种输入影响很大：1-shot SST-2 上，未校准为 66.5，用"N/A"为 74.2，用"the"为 69.1，三者集成为 79.0（[Zhao et al.](https://arxiv.org/abs/2102.09690)）。Batch Calibration 进一步记录了失败：在 QNLI 上，"Question: N/A, Sentence: N/A"会被模型理解为"N/A 蕴含 N/A"，从而偏向 entailment，**内容无关 token 反而会引入额外偏置**（[Batch Calibration](https://arxiv.org/abs/2309.17249)）。

【推断】这和 R1 观察到的"Zhao 式空问题校准压垮弃答"是同一个机制。问题换成 N/A 之后，"Unable to answer"对模型来说是**语义上正确**的答案，p_cf(弃答) 很高，除以它就把弃答概率压没了。对弃答选项而言，内容无关输入并不是内容无关的。没有论文直接研究过这个交互，以上解释是推断。

NOTA 文献则为 R1 现有的"在非弃答选项上重归一化"提供了正面理由。即便是 52B 的模型，也仍然"strongly biased against"选 none-of-the-above（[Kadavath et al.](https://arxiv.org/abs/2207.05221)）。28 个 LLM 在 NA 为正确答案时准确率一致下降 30–50%，例如 DeepSeek-V3 从 90.8 掉到 65.7（[Tam et al.](https://arxiv.org/abs/2503.01550)）。弃答选项的概率与内容选项不可比，把它们放进同一个归一化会同时放大两端的偏差。论文里应把这一设计写成有文献依据的决定，而不是实现细节。

先验分支还有几种替代构造，各自测量的东西不同：

| 构造 | 测量的是什么 | 先例与要点 |
|---|---|---|
| 只读题目（当前做法） | 证据相对语言先验的增益 | 与 PMI_DC、CAD、M3ID、RED 相同；但混入了 prompt 长度、格式和"没有视觉 token"三个因素 |
| 等长黑帧 | 同上，但控制了格式 | BICR 用纯黑图；VDD 的经验是加噪图、全零图效果不稳定，默认用无图（[VDD](https://arxiv.org/html/2403.05262)） |
| 其他视频的帧，或打乱的记忆 | 答案是否依赖**这份**证据 | LUMINA 用随机文档而非空上下文作对照（[LUMINA](https://arxiv.org/html/2509.21875v3)） |
| 向均匀收缩的 Q 分支 | 避免先验过尖导致过度否决 | 见下段 CF-VQA |

收缩先验分支也有先例。CF-VQA 发现，反事实分支用**均匀分布假设**远好于用真实先验：HM 融合下 51.27 对 46.29，SUM 融合下 55.05 对 38.06。它还用一个按 KL 学出的常数，让反事实分布的锐度与主分支匹配（[CF-VQA](https://arxiv.org/abs/2006.04315)）。CDA 去掉 null-prompt 校准后，NQ 上的 RS 从 62.95 跌到 47.89，说明在比较两路之前先各自校准很关键。【推断】对 R1 来说，无标签的做法是对 p'_Q 做温度缩放或熵匹配，让它不比 p'_E 更尖锐，然后再比较。Batch Calibration 支持的在线滚动均值天然适合流式场景，可以单独去掉与问题无关的选项字母或位置偏置，让 p'_Q 只承担"针对这道题的先验"。

【推断】最值得一试的是**只去掉记忆**的对照分支。ST-CueGate 只拿掉线索，保留帧、问题和前缀。如果 ReadPast 想让 R1 进入记忆的叙事，Q 分支就应是"同样的帧，但没有文本时间线"。这时 Δ 度量的是"记忆是否支持 o*"，而 R1 在 SimpleStream 上自然无法使用，这就把"R1 与记忆无关"变成了一个可以被证伪的命题。风险是这个变体可能丢掉大部分 HLD 收益，因为 HLD 题与当前画面同样无关。但无论结果如何，都能提供信息。

## OVO 在结构上看不见代价，必须把弃答选项注入可答题

HLD 和 RGB 的 negative rejection 是同一类协议：测试集里只有应该弃答的样本，所以只能量拒答率，量不到"该答时却拒答"（[RGB](https://arxiv.org/html/2309.01431)）。

- **HLD 的定义很模糊**：OVO 正文只有一句定义 "Ask questions irrelevant to existing video inputs"，没写选项怎么构造，也没写正确答案是否总是弃答（[OVO-Bench](https://arxiv.org/html/2501.05510)）。FOLIO 附录给出 HLD 共 186 题，"刻意与现有视频无关"（[FOLIO](https://arxiv.org/html/2607.13298)）。"金标恒为弃答"目前只来自我们自己对数据的检查。
- **R1 在 HLD 上不可能丢分**，因为它只会把答案往弃答方向改。Mirage 对 VCD 等方法的复现警告的正是这种情况：对比解码在 POPE 上的增益主要来自单向推高 Yes 比例，"Answer Yes if possible"这种伪基线在 COCO Adversarial 上拿到 83.7，比 VCD 的 81.9 还高。作者要求避免单向修改，并同时报告"纠正了错误答案"和"破坏了原本正确答案"的计数（[Mirage](https://arxiv.org/html/2504.10020)）。
- **HLD 的绝对值高度依赖协议**：同一个 Dispider 在不同论文里是 4.30 或 45.43，LLaVA-Video-7B 是 7.53 或 51.53；Qwen3-VL-8B 在 SPARE、StreamScout、SimpleStream 中分别是 11.83、43.55、52.1（[OASIS](https://arxiv.org/html/2604.17052v1)、[SPARE](https://arxiv.org/html/2610.14671)、[StreamScout](https://arxiv.org/html/2609.00291)）。只报"HLD +13～15"，说服力很弱。

要让代价可见，标准做法是**把弃答选项同样加到可答题上**：
- MM-UPD 把"None of the above"和对应指令也加到标准题上，理由是 "to make a fair comparison"。它的主指标是 Dual accuracy：标准题和配对的不可解题都答对才算对（[MM-UPD](https://arxiv.org/html/2403.20331)）。
- Tam 等的 NA-as-distractor 设定让平均准确率从 0.738 降到 0.674（[Tam et al.](https://arxiv.org/html/2503.01550v1)）。
- Ling 等把"Unknown"注入可答题：在四选一选择题上，准确率变化 +0.4 到 −4.2，弃答率 0.2–7.4%。把"Unknown"换成随机词"Triangular"，也能在 FLD 上触发 30% 以上的弃答（[Ling et al.](https://aclanthology.org/2026.emnlp-main.549.pdf)）。

Ling 等的最后一点说明，注入实验至少要分三档：不加选项、加选项但不用 R1、加选项并用 R1。这样才能把"选项本身诱发的弃答"和"R1 造成的弃答"分开。选项本身确实有副作用：MM-UPD 里 LLaVA-NeXT-34B 加选项后，Dual 反而从 50.5 跌到 29.9。

量级上，R1 的 16–20% 明显高于这些 prompt 级选择题先例。放在 UVQA 的过度拒答尺度上，它高于 DPO 对齐的 Video-LLaVA（0.14），低于 SFT 对齐的 Video-LLaVA（0.50）（[UVQA](https://arxiv.org/html/2507.04976v1)）。两份调研笔记对 UVQA prompt 基线的读数不一致（0–0.02 和 0.08–0.12），引用前需核对原表。

指标不必自造，现有数字都能对上已有定义：

| R1 的现有数字或待补量 | 对应的已有指标 | 出处 |
|---|---|---|
| 16–20% 已答对的记忆题被改成弃答 | UVQA 的 Excessive Refusal；也等于 1 − Selective Prediction Recall | [UVQA](https://arxiv.org/html/2507.04976v1)；[Srinivasan et al.](https://arxiv.org/html/2402.15610v1) |
| 抓到 26–35% 的 HLD 幻觉答案 | 以"base 会答错"为应弃答标签时的 abstain recall | [Feng et al.](https://arxiv.org/html/2402.00367) |
| 待补：被翻转的可答题里原本答错的比例 | abstain precision | [Feng et al.](https://arxiv.org/html/2402.00367) |
| 待补：答对 +1、答错 −c、弃答 0 的总分，报 c=1/10/100 | Effective Reliability Φ_c | [Reliable VQA](https://arxiv.org/pdf/2204.13631) |
| 待补：HLD 题与可答题配对计分 | Dual accuracy，以及审稿人建议的 Dual/Standard | [MM-UPD](https://arxiv.org/html/2403.20331)；[OpenReview MM-UPD](https://openreview.net/forum?id=K4YMFdx2Z2) |

几点补充。Srinivasan 等报告，BLIP2 在 90% 可靠度目标下对约 94% 的正确预测弃答，说明选择性预测的代价可以非常大。Φ_c 有一个好性质：只在答错时弃答，Φ 就等于准确率。MM-UPD 的一位审稿人批评 Dual 把通用能力和拒答能力绑在一起，建议看"标准题答对的前提下是否正确拒答"，正好对应"base 答对的题里 R1 保留了多少"。Wen 等的综述认为没有单一指标够用，错误回答率和错误弃答率必须同时看（[Wen et al.](https://arxiv.org/html/2407.18418)）。

【推断】最能帮助做决定的一个数，可以直接从 Φ_c 的定义推出来：
- R1 每把一道答对的题翻成弃答，损失 1 分；每把一道答错的题翻成弃答，挽回 c 分。
- 所以 R1 在可答题上能让 Φ_c 变正，当且仅当 c 大于"翻转的答对题数 ÷ 翻转的答错题数"。把这个比值记为**盈亏平衡罚分 c***。
- 等价地，可以看**选择性比**：R1 在答错题上的翻转率 ÷ 在答对题上的翻转率。随机弃答的比值是 1，比值越高，16–20% 的误弃答越可能是值得付的代价。

换句话说，16–20% 这个数本身不能判 R1 出局，选择性比才能。ClashEval 给过同一逻辑的对照：在相同的 8.5% 先验使用率下，随机替换的准确率只有 57.5%，校准方法为 75.4%。

对照行要能逐条回答审稿人的追问：

| 对照行 | 做法 | 回应的质疑 | 先例 |
|---|---|---|---|
| 不弃答（base） | 原模型直接作答 | 参照点 | Whitehead 表中的"—"行（[Reliable VQA](https://arxiv.org/pdf/2204.13631)） |
| 永远弃答 | 有弃答选项就选弃答 | "HLD 金标恒为弃答" | 按定义 Φ_c = 0；Feng 等把近乎总弃答的方法记为无效（[Feng et al.](https://arxiv.org/html/2402.00367)） |
| 只靠弃答 prompt | FOLIO K.3 或 D-HSM 式指令 | "一句 prompt 就够" | UVQA 审稿人要求补做，作者放进附录 A.9（[OpenReview UVQA](https://openreview.net/forum?id=P9VdRQOyqu)） |
| 等弃答率随机弃答 | 按 R1 的翻转率随机翻转 | "R1 没有选择性" | ClashEval 随机对照；Mirage 伪基线 |
| 等弃答率低置信弃答 | p'_E(o*) 最低的 k% 改成弃答 | "R1 只是低置信过滤" | Reliable VQA 的 MaxProb |
| blind 预测 | 直接用 p'_Q 的 argmax 作答 | "R1 只是把模型推向 blind 行为" | OVO 的 Blind GPT-4-turbo 在 HLD 上得 70.05 |
| oracle | 只在 base 答错时弃答 | 上界 | Whitehead 表中的 Best Possible 行 |
| 负对照 | Zhao 式 N/A 校准；含弃答选项的全选项 PMI | 先验分支的构造是否关键 | Zhao 与 VDD 的构造消融 |

## 写法：把 HLD 收益让出去，把代价和选择性留在正文

流式与幻觉文献对这类模块有三种包装档次：
- **命名方法 + 完整消融**：TCD 做了 α、β 扫描和扰动方式对比；SEASON 在四个通用视频基准上检查了原有能力是否保住；RED 有组件消融，还对 selector 做了匹配、错配、随机和 oracle 对照。
- **埋在训练贡献里**：SPARE 把弃答写进贡献 1，但消融只有"有/无 LoRA"两行，无法把弃答和 LoRA 的其他效应分开。
- **一句话带过或不提**：FOLIO 只说一句 "conservative answer calibration"；OneStreamer 的 99.5、StreamScout 和 D-HSM 都没有解释自己的 HLD。

【推断】R1 贡献了总分 +2.2～2.6。在这种情况下用第三档的写法，会被读成在隐藏增益来源。团队自己的分析已经得出"R1 = HLD 伪影"的结论，审稿人只会更快得出同样的结论。

单列 HLD 的写法已有现成先例：
- **StreamOPD**：摘要 headline 写的是 "OVO-Bench excluding its hallucination-detection subtask"，提升 9.1 点，达到 71.9%；HLD 另报 57.0，并明确当作弃答诊断（[StreamOPD](https://arxiv.org/abs/2608.16320)）。
- **SimpleStream**：§5.3 专节论证 "HLD is not a memory task"，指出把 HLD 放在 Backward Tracing 下 "conflates two distinct abilities"，并另外定义了只含 EPM 与 ASI 的记忆指标。这里要纠正一个常见误读：SimpleStream 主表的 Avg 其实**包含** HLD，真正在 headline 中排除 HLD 的是 StreamOPD（[SimpleStream](https://arxiv.org/html/2604.02317)）。

公开审稿意见里没找到直接针对 HLD 的批评，但相邻的批评都有：
- UVQA 的审稿人要求补一个 "Say can't answer if you are not sure" 式的 prompt 基线，并担心 "models might drop performance on other tasks"（[OpenReview UVQA](https://openreview.net/forum?id=P9VdRQOyqu)）。
- AbstentionBench 的审稿人批评，按构造使题目不可答的 split 上的收益 "could fail to transfer"（[OpenReview AbstentionBench](https://openreview.net/forum?id=OkHC30LLpO)）。"刻意与视频无关"的 HLD 正是这类按构造不可答的题。
- UVQA 只在附录 A.2 承认过度拒答上升。R1 的代价更大，正文的局限段至少要有一句带数字的说明。

| 定位 | 需要先拿到的证据 | 放置 | 主要风险 |
|---|---|---|---|
| 核心贡献 | 重设计版在注入集上不被弃答 prompt 支配，选择性比明显大于 1，在 OVO 之外的配对集上也成立 | 正文独立一节 | "HLD 是伪影"的质疑全部落在主贡献上；需要额外基准 |
| **有名字的答案端插件（默认推荐）** | 注入实验的双侧数字和前述对照行齐全 | 主表单独一行，正文一小节给精简的双侧数字；扫描、先验分支消融和分桶分析放附录 | 审稿人会追问代价，必须正面写"与记忆无关" |
| 分析 / 诊断 | 选择性比约等于 1，或被弃答 prompt 支配 | 附录或讨论节，作为"HLD 可被免训练规则刷分"的证据 | 失去 +2.2～2.6 的总分；但能反过来支撑 SimpleStream 的批评，增强记忆主张的可信度 |

理论包装最自然的是 PMI / 对数 Bayes 因子，谱系可以直接引 RED 的 Eq. 2、M3ID、CAD 和 PMI_DC。也可以用 CF-VQA 的语言写成"总间接效应的符号检验"，顺带引用它"均匀假设优于真实先验"的结果，说明为什么要收缩 Q 分支。关键是两点：
- 明确写出"Bayes 因子 ≤ 1 不等于答错"。
- 像 PMI_DC 坦白 ARC-Easy 失败那样，把按 p'_Q(o*) 分桶的误弃答率作为失败模式分析放出来。

如果要证明信号本身有效，可以仿照 LUMINA 对信号方向做单侧统计检验（[LUMINA](https://arxiv.org/html/2509.21875v3)），再报告 Δ 区分"base 答对 / 答错"的 AUROC。【推断】方向检验只能说明信号方向对，不能说明它是个好检测器，所以 AUROC 不能省。

应对"HLD 收益是基准造成的"这一质疑，最稳的策略是先承认，再拆解。【推断】具体步骤：
1. 在表注里写明："HLD gold is always 'Unable to answer'; R1 can only abstain, hence cannot lose HLD points"。同时引用 SimpleStream §5.3 和 OVO 自己 Blind GPT-4-turbo 的 70.05。
2. 说明 ReadPast 的记忆主张只依赖不含 HLD 的数字。
3. 把"R1 加到 SimpleStream 上同样有效"主动写成"与骨干无关的答案端插件"，不要等审稿人自己发现。
4. 用注入实验的双侧数字、选择性比和等弃答率对照，证明 R1 的弃答不是随机的。

措辞上不要把 R1 称为通用的幻觉缓解方法。更稳妥的定位是：在带弃答选项的选择题上，以 X% 的过度弃答换取 Y% 幻觉召回的选择性预测规则。

## 按优先级排列的改进建议

| 优先级 | 行动 | 成本 | 能证伪什么 |
|---|---|---|---|
| P0-1 | 在实时、EPM、ASI 上注入"Unable to answer"（可加 StreamingBench 的记忆类选择题），跑三档：不加选项 / 加选项 / 加选项+R1，可再加一档随机词选项。报告准确率、弃答率、Excessive Refusal、答错题与答对题各自的翻转率、选择性比、c*、Φ_1 和 Φ_10 | 纯推理：每题 E、Q 两次前向 × 两档。如果离线估计 16–20% 时的逐题 logits 已缓存，主要是写脚本，约一天 | **"R1 是有选择性的证据检验"**。若选择性比≈1，或 c* 远大于 10，R1 与等量随机弃答没有区别，直接降为附录分析 |
| P0-2 | 补对照行：永远弃答、只靠弃答 prompt（FOLIO K.3 / D-HSM 式措辞）、等弃答率随机弃答、等弃答率低置信弃答、blind 预测、oracle。OVO 原版和注入集都要跑 | 弃答 prompt 需要在 OVO 和注入集上各做一次完整推理；其余复用 logits，几小时 | **"R1 有存在必要"**。若弃答 prompt 在"HLD 召回–过度弃答"平面上支配 R1，R1 就没有理由保留 |
| P0-3 | 重排主表：headline 用不含 HLD 的总分，HLD 和含 HLD 的总分另列；"+R1"单独一行并加表注；补 SimpleStream+R1 一行；局限段写一句带数字的代价 | 只改写作，半天 | **"记忆收益独立于 R1 和 HLD"**。若去掉 HLD 后对 SimpleStream / D-HSM 的优势消失，论文框架必须改，与 R1 无关 |
| P1-4 | 阈值与门控扫描：Δ ≤ −δ、置信门、JSD 门、CDA/SABER 式格子决策。画"HLD 幻觉召回 vs 可答题过度弃答"的 Pareto 曲线，用"翻转预算"在可答任务上无标签地定 δ | 复用 logits，不需要额外前向，几小时 | **"阈值 0 是合理的工作点"**（PVI 的拐点在 0.5 bit）。以及"存在某个变体，能把过度弃答压到 prompt 级先例的量级（约 ≤7%），同时保留可观的 HLD 召回" |
| P1-5 | 失败分桶：按 p'_Q(o*) 的十分位、按题型（EPM / ASI / 实时）统计误弃答率 | 几小时 | **"误弃答集中在先验就能答对的题"**和**"R1 专门惩罚记忆题"**两个假设 |
| P1-6 | 先验分支消融：只读题目 / 等长黑帧 / 他视频帧 / 只去文本时间线 / 温度收缩的 Q / Zhao 式 N/A（负对照） | 每个变体约等于一遍 OVO 推理（含注入集） | 效应来自"证据 vs 先验"，还是来自格式与长度混杂。"只去文本时间线"的版本可以证伪"R1 能与记忆挂钩"：这个版本在 SimpleStream 上无法使用 |
| P2-7 | 在 OVO 之外做配对或混合验证：UVQA 的 300+300 评测集、VideoHallucer 式成对计分，或用 OVO 的 HLD 题与可答题自建 Dual 配对 | 中到高：要构造数据，开放题还需要判别器 | 能否泛化到"弃答不恒为金标"的协议。只有走"核心贡献"路线时才必需 |
| P2-8 | 理论与定位：用 PMI / 对数 Bayes 因子写法，引 RED、M3ID、CAD、PMI_DC、CF-VQA；核对同期 ADP 与 RED 和 R1 的重叠 | 写作，约一天 | **新颖性主张**。若 ADP 已经做了有/无证据对比式弃答，需要改写差异点 |
| P2-9（可选） | 用少量带标注的校准集做共形风险控制，给过度弃答率一个分布无关的上界 | 计算量很小，但要放弃"无标注"这一卖点 | 给出可部署的风险保证。若在保证下 HLD 召回很低，就反证 R1 不实用 |

【推断】建议的执行顺序：
1. P0-3 立即做。
2. P0-1 和 P0-2 一起跑。
3. P1-4 复用同一批 logits，紧接着做。

决策规则如下。若存在某个变体同时满足三条，R1 就以有名字的插件进入正文：
- 选择性比明显大于 1。
- 在相同弃答率下胜过随机和低置信对照。
- 在 Pareto 平面上不被弃答 prompt 支配。

任一条不满足，就降为附录诊断。"约 ≤7%"这条参考线取自 Ling 等 prompt 级选择题注入实验的弃答率上限，是经验锚点，不是文献给出的标准。

## 结论

这轮调研改变的不是"R1 有没有用"的答案，而是这个问题该怎么问。HLD 上的 +13～15 在结构上无法证伪：R1 只会往弃答方向改，HLD 的金标又恒为弃答，所以这个数不包含任何关于 R1 好坏的信息。真正有信息量的是可答题上答错与答对两类题的翻转率之比，而这个比值在已有 logits 上几乎零成本就能算出来。

CAD→AdaCAD、VCD→Mirage 这两条文献演化线说明，社区认可的叙事是"固定强度的有/无证据对比在证据冗余时会误伤，我们用无标签的门控把它修好"；被惩罚的是在只测一侧的基准上拿单向增益。R1 目前在后一边。三处改动恰好能把它挪到前一边：加门控、用翻转预算定阈值、改成只去记忆的对照分支。

另一个不那么明显的推论是，"R1 与记忆无关"现在是负债，但可以变成资产。一条路是诚实地把 R1 写成与骨干无关的插件，把 ReadPast 的记忆主张完全建立在不含 HLD 的数字上。另一条路是把先验分支改成只去掉文本时间线，让 Δ 直接度量"记忆是否支持这个答案"，这样 R1 第一次有了与记忆挂钩、并且能在 SimpleStream 上被证伪的形式。两条路都比维持现状更经得起审稿。
